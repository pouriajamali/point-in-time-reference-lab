# Contributing

Use new synthetic corrections and explicit as-of queries. State which data is rejected, which earlier knowledge result must stay unchanged and which executable counterexample proves it. Preserve original correction receipts and source attribution.

Start with UTC/units/presence/response tests, then real range constraints and native API/CLI/PG history oracle. Do not copy the split algorithm into the reference oracle or sort knowledge by observed wall time. Keep private fixture connection files out of commits/issues.

Multiple instruments, extensions, external feeds/accounts, restore/lineage recovery or real trading require a separately reviewed scope. Existing career/portfolio/private/shared assets remain outside this lab.
